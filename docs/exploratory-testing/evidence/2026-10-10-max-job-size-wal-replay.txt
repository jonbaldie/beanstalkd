## Replay script: maxsize_followers.sh IMAGE MAXSIZE [beanstalkd args]
```sh
#!/bin/sh
# Replay: one job of exactly max-job-size, followed by small jobs; restart; which survive?
# Usage: maxsize_followers.sh IMAGE MAXSIZE [extra beanstalkd args...]
set -u
IMG=$1; MAX=$2; shift 2
LBL=xt-run=20261010; V=xt-mf-$$; C=xt-mf-$$
docker volume create --label $LBL $V >/dev/null
run() { docker run -d --label $LBL --name $C -p 127.0.0.1::11300 -v $V:/data $IMG beanstalkd -p 11300 -b /data "$@" >/dev/null
  P=$(docker port $C 11300/tcp | head -1 | sed 's/.*://'); sleep 1; }
run "$@"
echo "== start 1: beanstalkd -p 11300 -b /data $*"
python3 -I - $P $MAX <<'PY'
import socket,sys
s=socket.create_connection(("127.0.0.1",int(sys.argv[1])),timeout=5); f=s.makefile("rb"); m=int(sys.argv[2])
for n in (5, m, 5, 5):
    s.sendall(b"put 0 0 60 %d\r\n"%n + b"z"*n + b"\r\n"); print("put %d bytes ->"%n, f.readline().decode().strip())
s.sendall(b"stats\r\n"); h=f.readline(); y=f.read(int(h.split()[1])+2).decode()
print([l for l in y.splitlines() if l.startswith("current-jobs-ready")][0])
PY
docker stop $C >/dev/null; docker rm $C >/dev/null
run "$@"
echo "== start 2 (same volume) container log:"; docker logs $C 2>&1
python3 -I - $P <<'PY'
import socket,sys
s=socket.create_connection(("127.0.0.1",int(sys.argv[1])),timeout=5); f=s.makefile("rb")
for i in (1,2,3,4):
    s.sendall(b"peek %d\r\n"%i); h=f.readline().decode().strip()
    if h.startswith("FOUND"): n=int(h.split()[2]); f.read(n+2); print("peek %d -> FOUND, %d bytes"%(i,n))
    else: print("peek %d -> %s"%(i,h))
s.sendall(b"stats\r\n"); h=f.readline(); y=f.read(int(h.split()[1])+2).decode()
print([l for l in y.splitlines() if l.startswith("current-jobs-ready")][0])
PY
docker rm -fv $C >/dev/null; docker volume rm $V >/dev/null
```

## Root cause (upstream beanstalkd v1.13, unpatched by this repo)
prot.c:1344  c->in_job = make_job(pri, delay, ttr, body_size + 2, c->use);   /* put accepts body_size <= limit; stored size includes CRLF */
file.c:226 / file.c:351  if ((size_t)jr.body_size > job_data_size_limit) { warnpos(... "is too big"); goto Error; }
  -> stored size (body+2) is compared with the user-facing limit, so bodies of limit-1 and limit bytes fail replay;
     readrec returns 0 at Error, so the rest of that binlog file is not read.
